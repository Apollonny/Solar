# Solar 2D gameplay

1. Read the current main scene, input actions and relevant scripts before changing them. Keep the existing control scheme and assets unless the user requests a change.
2. Choose the smallest visible mechanic: player movement plus its immediate interaction. Keep `main.tscn` playable and remove `StarterScreen` when the actual game replaces it.
3. Apply `solar-ecs`: data in `components/c_*.gd`, composition in `entities/e_*.tscn` and `e_*.gd`, behavior in `systems/s_*.gd`. A `CharacterBody2D` entity owns its physics node; its system sets velocity and calls `move_and_slide` in the physics loop. Do not paste an upstream all-in-one player controller unchanged.
4. Define needed InputMap actions in `project.godot`. Poll continuous actions for movement and use event-driven input for discrete UI/game actions. Keep physics motion in `_physics_process` and use the API's correct delta semantics.
5. Set collision shapes, layers and masks deliberately. A visible sprite alone does not supply collision. Verify floor/obstacle/trigger behavior relevant to the requested mechanic.
6. Ensure gameplay nodes are instanced under the main scene, visible and inside the active camera view. Keep the camera enabled and HUD on the intended CanvasLayer. Check canvas coordinates, anchors and viewport stretch before replacing working rendering settings.
7. Reuse local assets first; styled primitives can establish the mechanic while keeping a coherent palette. Use `solar-assets` for reference art, external packs or generation.
8. After saving script/scene changes, use `project_validate` for the relevant scope. If gameplay checks are permitted, inspect logs, the actual rendered frame and the changed interaction. A Running indicator or changed state does not prove visible content.

Search upstream guidance for the specific problem, such as `characterbody 2d jump`, `input handling`, `camera systems`, `tilemap`, `collision` or `ui containers`. Read only the examples you need. Verify unfamiliar APIs against the installed Godot version.
